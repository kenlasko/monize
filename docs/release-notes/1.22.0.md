# v1.22.0

Estimated amounts on imported cross-currency transfers are now recorded properly, marked on the row, flagged in every figure that includes one, and confirmable in one click.

## Transactions and import

- **Estimated amounts:** when an imported file holds a transfer into an account in another currency, Monize creates that account's side before its own file arrives. Its amount is now estimated at the exchange rate of the transfer's date, instead of copying the other side's figure, so 100 USD no longer becomes +100 EUR. If no rate is available for that pair and date, the row is not imported and the import result names them.
- **Estimated amount badge:** such a row shows an **Estimated amount** badge in every register layout. The state no longer lives in the description, so editing or clearing the memo cannot change it, and the old `PENDING IMPORT` text is removed from existing descriptions.
- **Confirm amount:** choose **Confirm amount** on a row to keep its estimate as the actual amount. Importing the other account's file, or editing the transfer to state a different amount, confirms it too. Confirming can be undone from the action history.
- **Find them:** search transactions for `is:provisional` (or `-is:provisional` for the rest).

## Reports and balances

- **Estimates are marked, not hidden:** account balances, net worth, custom reports, transaction analytics, the Cash Flow, Monthly Category Breakdown and Income vs Expenses reports, the payee and category panels, budget transfer actuals, the currency detail page, the AI assistant and MCP keep the estimate in their totals and say how many estimated amounts a figure includes.
- **No artificial gain:** a cross-currency transfer with one confirmed side and one estimated side now nets to zero in the reporting currency, rather than showing a cash movement that never happened.

## Languages

- Every new string is translated in all supported languages.
